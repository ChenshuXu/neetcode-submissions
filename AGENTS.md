# NeetCode submissions

This repository contains synced submissions in `Data Structures & Algorithms/` and
local interview exercises in `custom_practice/`. It has no repository-wide build.

## Task scope

- Follow the requested mode: hints, explanation, review, or implementation. Hints and
  contract questions do not authorize revealing a full solution or editing an attempt.
- For requested edits, carry the change through relevant verification. Resolve routine
  implementation choices from local evidence; ask only when missing information changes
  the problem contract or authorized scope.
- Read the target exercise's README, candidate code, and relevant tests first. Follow
  imports and callers when changing shared behavior; load other exercises only as needed.
- Preserve the user's structure and unrelated edits. Keep intentional starter stubs unless
  asked to solve them. Do not rewrite synced submissions as incidental cleanup.

## Implementation and verification

- Use the existing standard-library runner and exercise adapters. See
  [practice workflow](custom_practice/README.md) for commands and template instructions.
- Prefer the smallest readable change that satisfies the contract. Keep reported interview
  facts separate from local practice assumptions; do not alter expected values to hide a bug.
- Run the affected exercise's checks after code changes. For shared runner changes, check
  its callers and cover affected behavior, including failure reporting and input isolation.
  Expand verification only for a changed dependency, failure, or unresolved risk.
- For documentation-only changes, check paths, commands, and `git diff --check`.
  Intentional starters need not pass; report their status without filling them in.
- Summarize the change, checks and remaining limits concisely. A passing assisted solution
  does not establish timed, unaided interview readiness.

## Skills and context

- Reuse an available skill when its scope matches the request; read its relevant references
  on demand. Keep explicit user intent ahead of skill guidelines, subject to higher-priority
  instructions. If a skill blocks authorized work, identify the exact file and instruction.
- This file owns repository-specific guidance. Exercise READMEs own problem contracts;
  the practice README owns the shared workflow. Link to these instead of copying rules
  into new skill or workflow files. Global memory guidance remains in the user's vault.
